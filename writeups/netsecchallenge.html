// Overview

Net Sec Challenge is a TryHackMe room focused on network enumeration and Nmap fundamentals. The target exposes a handful of services — SSH, HTTP, SMB, an FTP server on a nonstandard port, and a small web challenge on port 8081 — and the room walks through identifying them, fingerprinting versions, extracting flags hidden in service banners, and finally evading a simulated IDS while scanning the host.

// Reconnaissance

Port Scanning

A single full-port scan with service detection and default scripts answers most of the room's questions at once:

$ nmap -sC -sV -p- <target_ip>

PORT      STATE SERVICE     VERSION
22/tcp    open  ssh         (protocol 2.0)
80/tcp    open  http        THM{...}
139/tcp   open  netbios-ssn Samba smbd 4.6.2
445/tcp   open  netbios-ssn Samba smbd 4.6.2
8081/tcp  open  http        Node.js (Express middleware)
10001/tcp open  scp-config?
10121/tcp open  ftp         vsftpd 3.0.5

The room's first three questions are answered directly by this output:

  • Highest open port under 10,000 — 8081
  • Open port above 10,100 — 10121
  • Number of open TCP ports — 7

Service Fingerprinting

Two flags are hidden in service banners that Nmap's fingerprinting picks up automatically. The SSH banner carries a flag in its version string, and the HTTP server header carries another:

$ nc <target_ip> 22
SSH-2.0-OpenSSH_8.2p1 THM{...}

$ curl -I http://<target_ip>/
Server: THM{...}

Port 80's service version value — the string Nmap reports in the VERSION column — answers the fourth question, and the banner flag answers the fifth. On the nonstandard FTP port, -sV reports the server version as vsftpd 3.0.5, which answers the sixth.

Pro tip: nmap -sV alone often reveals more than people expect — banners, version strings, and in this room, two of the flags. Always read the full service scan output before reaching for another tool.

// FTP Access

Brute-Forcing Credentials

The room provides two usernames gathered through "social engineering": eddie and quinn. I created a small username file with nano and pointed Hydra at the FTP service on port 10121:

$ nano users.txt
eddie
quinn

$ hydra -L users.txt -P /usr/share/wordlists/rockyou.txt ftp://<target_ip>:10121

[10121][ftp] host: <target_ip>   login: eddie   password: <redacted>
[10121][ftp] host: <target_ip>   login: quinn   password: <redacted>

Both accounts use weak, dictionary passwords, which is exactly why the room supplies a short username list — Hydra only has to try two logins per password rather than brute-forcing usernames and passwords together.

Retrieving the Flag

Logging in as quinn reveals a single file in the FTP root:

$ ftp <target_ip> 10121
Name: quinn
Password: <redacted>
230 Login successful.

ftp> ls
-rw-rw-r--    1 1002  1002    22 Feb 24  2026 ftp_flag.txt

ftp> get ftp_flag.txt
ftp> quit

$ cat ftp_flag.txt
THM{...}

That answers the seventh question. Note that the FTP server is listening on a nonstandard port — a good reminder to scan the full range rather than the default top 1000.

// IDS Evasion

The final question points at the web service on port 8081, which presents a small challenge: scan the host "as covertly as possible" without being detected by the IDS, with a live percentage meter showing the chance of detection.

The intended technique is a NULL scan — a TCP scan that sets no flags at all:

$ nmap -sN -Pn <target_ip>

PORT      STATE         SERVICE
22/tcp    open|filtered ssh
80/tcp    open|filtered http
139/tcp   open|filtered netbios-ssn
445/tcp   open|filtered microsoft-ds
8081/tcp  open|filtered blackice-icecap
10001/tcp open|filtered scp-config

Nmap done: 1 IP address (1 host up) scanned in 1.27 seconds

The page immediately displayed the success message with the flag, answering the eighth question. Interestingly, -Pn turned out to be unnecessary — the NULL scan works on its own. Other write-ups confirm that FIN (-sF) and Xmas (-sX) scans also work, since they exploit the same RFC 793 behaviour.

Web Challenge Flag THM{...}
If the scan doesn't register: a few people report that NULL scans from a local Kali box don't always trigger the challenge. Running the same command from TryHackMe's AttackBox resolves it.

RFC 793 states that a closed port should respond to a packet with no flags set by sending an RST, while an open port should ignore it. Because nothing is set and the responses are silent, a NULL scan doesn't resemble a normal connection attempt — it looks like malformed or idle traffic. That's the whole trick, and it's why the port states come back ambiguous (open|filtered) rather than definitive.

The same family includes the Xmas scan (-sX, FIN+PSH+URG), the FIN scan (-sF), and the Maimon scan (-sM). All exploit the same RFC behaviour and are worth having in your toolkit.

// Verdict

A genuinely fun room that rewards understanding how Nmap's scan types work rather than how to tune a timing template. The banner flags are easy points, the FTP brute-force is standard, and the IDS puzzle is the real test — it's the one room in this set where reading the client-side code paid off more than any tooling.

→ 7/10 — recommended for anyone getting to grips with Nmap flags.
